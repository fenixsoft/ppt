执行环境 / Execution Environment

AI 永远在沙箱里干活；越靠近生产，人的介入越集中在高风险决策点。

试验区

Repo + Filesystem

代码库与文件系统

AI 的全部工作对象都在仓库内：改动可追踪、可回滚、可评审

破坏力：零——改错了大不了回滚
→
隔离区

Shell / Container / Worktree

容器与隔离工作树

试错被限制在容器内；多任务各用各的工作树，互不踩脚

破坏力：有界——爆炸半径 = 一个容器
→
生产区

Preview / Staging / Prod

预发与生产

发布必须过门禁：数据变更、权限变更、上线动作

破坏力：真实——人守在这里，逐项放行
管理含义：风险控制不靠"相信 AI 守规矩"，靠环境分层——破坏力被容器和门禁逐层截留。 人不是不在环上，而是只在环上的关键点位：高风险决策。这同时就是问责链的落点——出问题时，能说清是谁批的、批了什么。
Anthropic 工程方法 · 2026-10
三区模型的本质是"爆炸半径管理"：试验区零风险、隔离区有界风险、生产区真实风险+人工门禁。图上红字"Human review only at high-risk decisions"就是这个意思。对管理层的关键句：人在环上的唯一点位=高风险决策=问责落点，这三个"点"是同一个点。
