第③层 / Orchestrator + Agentic Loop · 执行循环

人在环外，AI 在环内：取上下文 → 动手 → 看结果 → 自查，循环直至达标。

1

Context

取上下文

读文件、搜代码、查 git 历史、调工具——先搞清现状再动手

→
2

Action

动手执行

改代码、跑命令、调用工具——在授权与门禁允许的范围内操作

→
3

Observe

观察结果

命令输出、lint、类型错误——机器反馈直接回到 AI 手里

→
4

Verify

自查验收

达到目标了吗？违反约束了吗？——像验收人一样端到端验证

↻ 未达标 → 带着问题回到第 1 步，循环直至完成（Repeat until done）；整个循环不需要人在线
官方最佳实践的核心：给 AI 配"自查手段"

让 AI 像真实用户一样用浏览器端到端验证功能，而不是"改完代码就算做完"——验证工具的有无，直接决定产出质量

Anthropic 实测最大教训

没有 Verify 环节，AI 会提前宣布胜利：功能没通过也标记"完成"。后续记忆层的功能清单就是专治这个毛病

管理含义

把"质量意识"内置进执行循环，而不是靠事后人工抽检；人的时间只花在定目标和看最终产出上

Anthropic 工程方法 · 2026-10
四步循环就是 Claude Code 的"explore → plan → code → commit"工作法的运行时形态。对管理层只需要记住一件事：这个循环里没有"等领导审批"的环节，人的审批点被前移到了第②层的权限矩阵里——能在制度里写清楚的，就不该靠人肉卡点。
